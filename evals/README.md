# 评测：把「感觉不错」变成数字

`evals/questions.jsonl` 是一套 30 题的固定评测集，覆盖 6 份示例文档和 3 种典型失败场景。
`kb eval` 会跑完整 Agent 流程（检索 → 工具调用 → 回答），再用另一个 LLM 调用判分，
最后生成 `reports/baseline.md` 和同名 JSON。

## 数据集构成

| 分类 | 题数 | 说明 |
| --- | ---: | --- |
| agent | 7 | Agent 循环、消息结构、流式、缓存、结构化输出 |
| api | 4 | agent-lab 的工具、安装、降级、安全边界 |
| uv | 2 | uv / pip+venv / 锁文件 |
| fastapi | 3 | 流式响应、SSE vs WebSocket、同步 vs 异步 |
| rag | 5 | 四步流程、切块、引用、指标、向量库取舍 |
| ops | 4 | 500 排查、连接耗尽、发布清单、复盘 |
| interview | 2 | 项目表达、注入防护 |
| unanswerable | 3 | 资料里故意没有答案，考拒答 |

其中 1 题要求跨两份文档（`q27`，安全实践同时出现在面试笔记和 agent-lab README）。

## 指标定义

| 指标 | 算法 | 关注什么 |
| --- | --- | --- |
| 来源召回率 | 期望文档 ∩ 本轮检索到的文档 / 期望文档 | 检索有没有找对材料 |
| 引用召回率 | 期望文档 ∩ 回答实际引用的文档 / 期望文档 | 模型有没有把材料用上 |
| 有引用回答占比 | 至少带一个 `[n]` 的可回答题 / 可回答题 | 引用习惯 |
| 回答质量 | LLM 判分 0–2 的均值 | 要点覆盖 + 无编造 |
| 忠实度 | 判分中 `faithful=true` 的比例 | 结论能否被引用片段支撑 |
| 拒答准确率 | 不可回答题中明确拒答的比例 | 不知道时敢不敢说不知道 |
| 接口错误率 | 重试后仍失败的题数 / 总题数 | 基础设施稳定性，单独统计 |

**错误题会从质量分母中剔除**。网关 401/500 不是模型能力问题，混进去只会污染结论。
每题最多重试 2 次。

## 判分 rubric

判分模型只看到：问题、参考要点、候选回答、回答实际引用的片段。

- **2 分**：覆盖所有参考要点，没有编造，引用能支撑结论。
- **1 分**：覆盖部分要点，或有个别无依据的补充。
- **0 分**：答错、答非所问，或大量编造。
- 对 `must_refuse` 题：明确说资料没有 = 2；含糊/猜测 = 1；编造 = 0。

判分只比较语义，不要求逐字复述参考要点。

## 跑一次

```bash
# 建议用干净的示例知识库，避免本地私人文档影响结果
mkdir -p /tmp/kb-eval-data/docs
cp data/docs/*.md /tmp/kb-eval-data/docs/
KB_DATA_DIR=/tmp/kb-eval-data uv run kb reindex

KB_DATA_DIR=/tmp/kb-eval-data uv run kb eval --out reports/baseline.md

# 快速冒烟
uv run kb eval --limit 5

# 只测检索，不调用判分模型
uv run kb eval --no-judge
```

单次全量约 7 分钟，花费主要在「每题 1–3 次 Agent 调用 + 1 次判分」。
报告包含每题耗时和 token 用量，便于估算成本。

## 基线结果

模型 `deepseek-v4.1-flash`，6 份文档 / 56 个片段：

| 指标 | 数值 |
| --- | ---: |
| 来源召回率 | 100% |
| 引用召回率 | 100% |
| 有引用回答占比 | 100% |
| 回答质量 | 1.96 / 2（98%） |
| 忠实度 | 100% |
| 拒答准确率 | 100% |
| 接口错误率 | 0% |
| 平均耗时 | 14.3s / 题 |

详见 [`reports/baseline.md`](../reports/baseline.md)。

唯一未满分的是 `q11`（stream_options 降级）：回答语义正确，但判分模型认为没有明确写出
「收到 400 后重试」和「无 usage 仍能完成解析」。这属于判分尺度噪声，保留在报告里不粉饰。

## 局限

- **单一判分模型**：和被测模型同源，可能偏好相似表达。换模型交叉判分会更稳。
- **30 题样本小**：适合回归对比，不适合宣称绝对能力。扩充到 100+ 题更有统计意义。
- **来源召回是文档级**：只检查文件是否命中，不检查是否命中正确段落。
- **判分有随机性**：`temperature=0` 仍可能有波动，比较版本时建议看多次均值。
- **不可回答题只有 3 条**：拒答率置信区间很宽，后续应补到 10 条以上。

## 加题格式

每行一个 JSON：

```json
{
  "id": "q31",
  "question": "问题",
  "category": "rag",
  "expected_sources": ["04-rag-practice.md"],
  "key_points": ["要点一", "要点二"]
}
```

不可回答题：

```json
{
  "id": "q32",
  "question": "资料里没有的问题",
  "category": "unanswerable",
  "must_refuse": true
}
```

要求：

- `id` 唯一，`must_refuse=true` 时不能写 `expected_sources`。
- `expected_sources` 用文档相对路径，和 `data/docs/` 下一致。
- `key_points` 必须能在文档里找到依据，不要写文档没有的结论。
