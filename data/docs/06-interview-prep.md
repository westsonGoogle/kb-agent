# 面试准备：如何讲 Agent 项目

## 一句话版本

“我用 Python 从零实现了一个 Agent：直连模型 API，手写 tool calling 的完整往返、SSE 流式解析和 Agent 循环，
在此之上做了带引用的本地知识库问答，CLI 和 Web 两个入口，测试全部离线可跑。”

## 面试官会追问什么

### 1. 为什么不用 LangChain？

不要贬低框架，讲清取舍：

- 学习阶段手写一遍，是为了知道框架帮你做了什么：消息拼装、工具 schema、流式增量、循环控制、错误回填。
- 生产阶段会选框架，因为要持久化、可观测、人工审批、多 Agent 编排，这些自己写成本很高。
- 手写过的优势是排障：模型不调工具、参数 JSON 截断、流式 usage 丢失，能直接定位到协议层。

### 2. 工具调用具体怎么走？

按消息顺序讲，不要背概念：

1. 请求里带 `tools`（JSON Schema）。
2. 模型返回 `finish_reason=tool_calls` 和 `tool_calls[]`，参数是字符串。
3. 把 assistant 消息原样存回历史。
4. 执行函数，把结果作为 `role=tool` + `tool_call_id` 回填。
5. 再次请求，模型基于结果生成最终回答。

强调两个细节：参数可能非法 JSON，必须容错；`tool_call_id` 必须一一对应，否则接口 400。

### 3. 上下文越来越长怎么办？

- 短期：只保留最近 N 轮 + 工具结果截断。
- 中期：把旧对话摘要成一条 system 消息。
- 长期：向量化存外部记忆，按需检索。
- 成本：稳定前缀放前面吃 prompt cache，动态内容放后面。

### 4. 怎么防注入？

- 工具结果和用户输入都当不可信内容。
- 文件工具做沙箱：resolve 后判断是否在根目录内，拒绝 `.env` 和私钥。
- 计算器不用 eval，用 AST 白名单。
- 高风险动作（写文件、执行命令、付款）必须人工确认。

### 5. 怎么评估效果？

不要只说“感觉挺好”。给三类指标：

- 任务成功率：固定 30 条问题，人工判定。
- 引用准确率：回答里的 [n] 是否真能支撑该结论。
- 成本与延迟：每次对话 token 数、首 token 时间、P95 延迟。

## 项目介绍模板（STAR）

- **S**：想搞懂 Agent 到底是不是“框架魔法”，同时需要一个能查自己文档的工具。
- **T**：两周内从零实现，不依赖 Agent 框架，能查天气/读文件/算数，再扩展成知识库问答。
- **A**：直连 API、手写循环与流式解析、工具注册表、沙箱、BM25 检索、引用登记、FastAPI + SSE、46+ 离线测试。
- **R**：代码开源，CI 全绿；知识库问答能给出可点击的来源，资料缺失时明确拒答。

## 不要说的话

- “用了大模型所以很智能”——面试官关心的是工程约束。
- “提示词调了很久”——除非能说出可复现的对比方法。
- “没有测试”——哪怕只有 10 条离线用例，也比没有强。
